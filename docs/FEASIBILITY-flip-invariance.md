## 8. 选项洗牌稳健性（S22）：模型是确定性的，但位置在决定答案

**为什么这一族最值得测，而且测量结果最难反驳**：S22 声称的不是"判得对"，而是
"判得稳"（gallery 标注：翻转率 **0.0217**）。这是一个**内部一致性**主张 ——
不需要人工标注对错，只要同一句话重复问、每次换选项顺序，就能测。

前面五次测量的失败都可以辩解为"我的标注集有偏、题面不合适"。**翻转率不行**：
同一句话、同一组选项、只有顺序变，答案却变，那与标注无关，是模型自身的问题。

### 方法（两步，刻意分开）

只测"换顺序会不会变"是不够的 —— 变化可能来自两个完全不同的原因，混在一起会
得出误导性结论：

- **A 顺序敏感**：固定顺序下稳定，但换顺序就变 → 可以靠固定选项顺序缓解
- **B 本身随机**：连顺序都不换，重复问就变 → 无法缓解

所以 `docs/measure-variance-vs-order.mjs` 对每条判定做两组测量：固定顺序重复 5 次、
以及把正确选项轮换到 3 个位置各问一次。

### 实测结果

```
  [order-sensitive] The build failed on Windows but passed on Linux.
      fixed order x5 : R R R R R       distinct=1   ← 完全确定
      by position    : R R x           distinct=2   ← 换个位置就错
  [order-sensitive] A customer reports they were charged twice for one order.
      fixed order x5 : x x x x x       distinct=1
      by position    : x x R           distinct=3
  [order-sensitive] A dependency has a published security advisory.
      fixed order x5 : x x x x x       distinct=1
      by position    : x x R           distinct=2
  [order-sensitive] An alert fired once and did not repeat.
      fixed order x5 : x x x x x       distinct=1
      by position    : x R R           distinct=2
  [stable         ] 其余 8 条：固定顺序与轮换位置下答案都一样
```

```
  fixed order x5 就会变（本身随机）        : 0/12
  固定顺序稳定、换顺序会变（顺序敏感）      : 4/12
  两者都稳定                              : 8/12

  固定顺序 60 次运行的准确率               : 20/60 = 33%
  gallery 标注的翻转率                     : 0.0217
```

### 三个结论

**1. 模型本身完全确定性。** 12 条 × 5 次固定顺序重复，**每一条的 5 次答案都完全
相同**（distinct=1）。所以不存在"采样随机性"这回事 —— 不稳定的来源被干净地隔离
成**顺序敏感**这一项。这比"有时准有时不准"好定位得多，也让"重试几次取多数"这种
缓解手段**完全无效**（重试会得到一模一样的答案）。

**2. 翻转率实测 0.333，gallery 标注 0.0217 —— 差 15 倍。** 也就是说"选项顺序打乱后
判定高度一致"这个说法在这批样本上不成立：**每三个判定就有一个会被选项顺序改变**。

**3. 3 选 1 的固定顺序准确率是 33%**，而随机基线是 33%。这批样本上模型没有表现出
优于随机的选择能力。

### 对"能不能自动化"的直接影响

调用方为了避开位置偏置，标准做法是**打乱选项顺序**（或在多个排列上取平均）。
这个测量说明：对这批判定，**打乱顺序会改变答案**。于是调用方陷入两难：

- 打乱顺序 → 答案不稳定，且无法靠重试收敛（模型是确定性的）
- 固定顺序 → 答案稳定，但那个稳定答案有 2/3 的概率是错的，而且稳定在"错"上

**两者不能同时成立。** 这与 `measure-routing.mjs` 里"正确选项在第 0 位 42%、第 1 位
50%、第 2 位 58%"是同一个现象的两个侧面。

### 与 gallery 的差异，以及它意味着什么

gallery 的 0.0217 来自模型自身的评测流程；这里是经 `POST /v1/systemone` 的真实协议
调用、用本仓构造的样本。两者差这么多，说明**不能把 gallery 的稳健性标注当作
"可以放心打乱选项"的依据**。

需要说清楚的是：这**不是说 0.0217 是编的**。更可能的原因是口径差异 —— 例如评测时
选项顺序是否固定、题面措辞是否固定、样本来自哪个分布。但这恰恰是问题所在：
**调用方无法知道自己的用法落在哪个口径里**，而一旦落到"会翻转"的那一侧，
自动判定就会给出随选项排版而变的结论。
