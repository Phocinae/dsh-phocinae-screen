## 12. 时延类演示（S24 上手 / S10 路由 / S11 微批 / G25 本地 vs API）

前十一族测的是**判定质量**；这四条声称的是**时延**。时延可以客观测量，但
**必须说明测量环境**：gallery 的 21.0ms 是 RTX 5090 fp16，本机是 **CPU**，所以
绝对值不可直接比较。能验证的是**结构性主张**。

`docs/measure-latency.mjs`（服务由发布到 PyPI 的 wheel 启动）：

### 1) 单次决策时延（本机 CPU）

```
  one choice question    n=20   min 13.6  p50 15.1  p90 16.2  max 16.7 ms
```

**本机 CPU 的 p50 是 15.1ms —— 比 gallery 标注的 RTX 5090 21.0ms 还快。**
这个差异本身不值得深究（机器、torch 版本、编译后端都不同），但结论是明确的：
**"必须 GPU 才能到这个量级"不成立**，CPU 上同一量级可达。

### 2) 时延随请求规模变化 —— "21ms/决策"不是常数

```
  state x1  (48 字符)    p50 15.2 ms
  state x4  (195 字符)   p50 18.8 ms
  state x16 (783 字符)   p50 32.1 ms      ← 长度 ×16，时延 ×2.1

  1 个问题    p50 15.0 ms
  4 个问题    p50 28.0 ms
  16 个问题   p50 69.9 ms                 ← 问题 ×16，时延 ×4.7
```

这是本测量最实用的一条：**时延是请求规模的函数，不是一个常数**。
把"21ms/决策"当作容量规划依据会低估长上下文、多问题的场景（本机实测 16 问题要 70ms）。

### 3) 微批确实摊销，但远不到 S11 声称的程度

S11 标注：微批 4 摊销后 **7.0ms/决策**，跑进 60fps 帧预算。

```
  batch  1   总 p50  15.4 ms    摊销 15.4 ms/决策
  batch  2   总 p50  28.7 ms    摊销 14.3 ms/决策
  batch  4   总 p50  53.7 ms    摊销 13.4 ms/决策
  batch  8   总 p50 106.3 ms    摊销 13.3 ms/决策
  batch 16   总 p50 213.8 ms    摊销 13.4 ms/决策
```

**方向对（批量确实降低单决策成本），但摊销幅度只有 13%**（15.4 → 13.3），
而 S11 声称的 7.0ms 相当于从 21ms 摊销掉 67%。也就是说：
- 若以 gallery 自己的 21ms 为基线，7.0ms 是 3 倍改善；
- 本机实测只有 1.16 倍改善。

**60fps 帧预算（16.7ms）这一条**：本机单决策 p50 15.1ms 确实在预算内，但 p90
16.2ms 已贴边、max 16.7ms 正好触线。所以"跑进 60fps"在**单决策、短上下文**下成立，
一旦 state 变长或多问题就不成立（x4 长度已 18.8ms）。

### 4) 本地 vs 远程（G25）

G25 标注：本地 21.0ms vs API 往返 1.51s。

本机测出的"远程 HTTPS 往返"是 **10.5 秒** —— 但这是**测量环境所致**（本网络对
huggingface.co 不通，请求一直等到 20 秒超时附近的连接失败），**不能当作 1.51s 的
反证**。这一点必须写清楚，否则就是拿一个坏掉的测量去否定别人的数字。

能说的只有量级：本地决策是**毫秒级**，任何远程调用都是**百毫秒到秒级** ——
两者不在一个量级，这一点无需测量也成立。G25 的具体数字（1.51s / n=40）本机
无法复核。

### 结论

四条里：
- **S24（三行上手）** —— 成立，且已由发布物验证覆盖（见模型仓 `tools/verify_published.py`）
- **S10（简单本地 / 复杂升级）** —— 本地时延成立；"升级"部分即 S06/G26，见第 11 节
- **S11（微批摊销）** —— **方向成立、幅度远不到**：实测摊销 13%，声称约 67%
- **G25（本地 vs API）** —— 量级关系成立，具体数字本机无法复核

所以时延族的共同结论与前十一族的"判定质量"不同：**模型确实快，CPU 上就是毫秒级**；
但把时延当常数用、或按声称的摊销倍数做容量规划，都会偏。
