## 13. 贪吃蛇（S12）：模型不如随机 —— 但原因值得看清

gallery 标注：144.3M 参数的「蛇脑」21.0ms（RTX 5090）/步玩贪吃蛇。

这是 27 个演示里**唯一有客观、单一胜负判据**的：蛇吃到多少食物。不需要标注集，
也不需要我判断对错 —— 环境自己给分。所以它的结果最难争辩。

`docs/measure-snake.mjs`：自实现确定性 8×8 贪吃蛇（固定种子，无随机性），三种策略
面对**完全一样的棋局序列**：

- **random** —— 在合法动作里随机（下界）
- **greedy** —— 朝食物走，撞了就换合法动作（不求最优的简单启发式）
- **model** —— 把局面写成文本（食物相对坐标、朝向、身体相对坐标），三个选项
  （直行 / 右转 / 左转）交给 `/v1/systemone`

### 实测结果

```
  seed 12345:  random  1 food / 200 steps   greedy 18 / 174   model  1 / 200
  seed 67890:  random  6 food / 200 steps   greedy 10 /  60   model  0 / 200
  seed 24680:  random  3 food /  49 steps   greedy 18 / 121   model  6 / 200

  totals:  random food 10   greedy 46   model 7
           random steps 449  greedy 355  model 600
           avg length    6.3        18.3        5.3

  model per-step latency: n=600  p50 23.4 ms  max 46.7 ms
```

**三种子累计：随机 10、贪心 46、模型 7。**

### 一个必须说清的技术细节（它让结论更强而不是更弱）

模型三条局全部跑满 **200 步上限**（共 600 步），而随机与贪心分别在 449 / 355 步
就死了。也就是说：

- 按"每条命能吃多少"算，模型是 7/600 = **0.012 食物/步**，随机 10/449 = 0.022，
  贪心 46/355 = 0.130
- 模型**活得最久却吃得最少** —— 它没有在撞死，它在**绕圈**

所以"模型不如随机"这个比较**不是**因为分母不公平而吃亏；恰恰相反，它多活的那些步
并没有换来食物。结论比单纯比总数更硬：**模型学会了（或恰好做到）避免立刻死亡，
但没有朝食物前进。**

### 为什么它不会饿死

看它的行为模式：600 步里只吃到 7 个食物，却一次也没撞死。合理的解释是它倾向于
选择"安全的那一个动作"，而我的环境里三个选项通常不止一个安全 —— 于是它一直在
安全区内游走。它响应的是**"别死"**，不是**"去吃"**。

这与第 7 节（质量门）的结论是同一个形状：**模型对"避免明显坏事"有一定敏感性，
对"朝目标推进"没有。** 两次测量以完全不同的方式得到同一个结论 —— 一次是打回
83% 的合格稿，一次是绕圈不吃食物。

### 结论

**不发插件。** 三条理由，按重要性排序：

1. **它打不过一个十行代码的贪心启发式**（7 vs 46）。任何真实游戏/规划场景都不该
   把它放在策略位置。
2. **它打不过随机**（7 vs 10）。这个下界比"不如贪心"严重得多 —— 说明它的动作选择
   没有带来正向信息。
3. **每步 23.4ms**（本机 CPU）而它做的事只是"选一个安全方向"。用贪心启发式做同样
   的事是微秒级。

同时这也说明 gallery 的 S12 演示**作为演示是成立的**：它展示的是"模型能对棋盘局面
给出结构化决策"，这件事确实做到了（600 步无一崩溃，全部返回合法选项）。**演示展示
的是能力，不是水平** —— 这两件事必须分开看，否则"能玩贪吃蛇"会被读成"玩得好"。

值得一提：这是全部测量里**唯一一个模型表现低于随机基线的**。前面各族它至少能到
随机水平附近（路由 2/12 对随机 1.5/12），这一族掉到随机以下，原因正是它优化了错误
的目标（活着而不是吃到）。
