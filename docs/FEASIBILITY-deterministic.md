## 4. 规则形状的决策点：模型不但没帮助，还会让系统变差

第 3 节测的六个决策点都没有「规则内核」，只能靠模型判。但 gallery 里还有一类
演示，判定**本身就是算术或规则**——S18 发票校验最典型：金额 × 税率 == 税额
是逐分可算的。所以真正该问的是：这类点上**加一层确定性规则**能不能达标？

`docs/measure-deterministic-first.mjs` 用 12 张发票测三种形态（6 张自洽、
6 张不自洽，不自洽的方式各不相同：税额算错、合计算错、合计被抹成整数、
差一分、税率用错、合计多写 10.00）。

### 实测结果

```
=== A) 纯规则（只做算术，完全不问模型）===
  -> caught 6/6 problems, 0 missed, 0 false alarms

=== B) 纯模型（把发票交给模型判"一致/不一致"）===
  MISS want=inconsistent got=consistent   P(inconsistent)=0.254  税额算错：应为 228.00，写成 200.00
  MISS want=inconsistent got=consistent   P(inconsistent)=0.215  税额对，但合计算错：应为 530.00
  MISS want=inconsistent got=consistent   P(inconsistent)=0.409  税额对，合计被抹成整数
  MISS want=inconsistent got=consistent   P(inconsistent)=0.362  合计差一分（118.99 vs 118.00）
  MISS want=inconsistent got=consistent   P(inconsistent)=0.224  税率用错：按 20% 而非 25% 算税
  MISS want=inconsistent got=consistent   P(inconsistent)=0.357  合计多写 10.00
  -> caught 0/6 problems, 6 missed, 0 false alarms
```

**模型一张都没抓出来。** 而且给出的 P(不一致) 全挤在 0.215–0.482 之间，
不管那张发票错得多明显：

```
Invoice
Net amount: 1200.00
VAT rate: 19%
VAT amount: 200.00      <- 应为 228.00
Total: 1400.00          <- 应为 1428.00
```

四行、两个数字对不上、上下文只有这些——模型判「自洽」，P(不一致)=0.254。
作为对照，纯算术在这一组上是 6/6、零误报，且能指出错在哪一分钱。

### 灰区更糟

规则读不出金额时（金额写成英文文字），模型的表现是**两条全错**，
而且两条的 P 差只有 0.019（0.567 vs 0.548）——等于没有分辨力。

这暴露了一个比"准确率低"更根本的问题：

> 一张规则解析不了的发票，**没有人能验证模型对它的判断**。

模型说"自洽"，调用方无从复核，于是拿到一个**虚假的保证**。一个校验门给出
无法验证的保证，比不给保证更危险——这正是「fail-closed」的反面。

### 结论

在这一类决策点上，**加模型会让系统变差**：准确率从 6/6 降到 0/6，可解释性从
"差一分钱"降到"P=0.254"，还多了一次网络调用和一份无法审计的自信。

所以正确的形态不是「模型 + 规则兜底」，而是：

1. **规则定夺**（可算的、可逐分核对的）；
2. **算不出来就说算不出来** —— 标记为「需人工」而不是猜；
3. 模型只用在"规则读不懂但人能读懂"且**结论可被独立复核**的场合。

第 3 条在这个项目里目前**找不到合格样本**：prose 那两条就是反例。所以本包
不发布这类插件，并把这条判据写在这里，供以后重新评估时对照。

## 5. 汇总：四类独立测量，同一个方向

| 测量 | 脚本 | 结果 |
|---|---|---|
| 上下文粗筛（S09/S20） | `measure-screen.mjs` | 含真正修复答案的块得 0.323（判可删）；儿歌得 0.691（判该留） |

四次独立测量指向同一个结论：**在这些判定域上，模型的判别力不足以支撑一个
会替用户下结论的插件。** 这不是保守，而是与项目自己的立场一致——模型卡如实
披露 JevBench 0.5455 未过门，`phocinae-guard` 也把 L1 默认关掉。

**什么情况下结论会变**：一个针对具体决策域做过校准的头（`phocinae-guard` 的
P1 就是这件事），加一套 200 样本以上、带留出集、且能给出**可独立复核**结论的
评测。上面四个脚本就是为此准备的——把新头接上去，它们会直接告诉你够不够格。
